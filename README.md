# NovelAI Prompt Studio
轻量的AIGC Prompt生成器，助力灵感与创意落地。

用中文寻找绘画标签，点击组合成英文 Prompt，再复制到自己的生图工具。NovelAI Prompt Studio 是面向 NovelAI 用户的可视化绘画提示词编辑器，提供内置双语词库、逐标签权重、收藏组合和个人标签库，支持电脑与手机浏览器，无需登录或 API 密钥。

每一个标签，都是灵感的起点。

**在线使用：[打开 NovelAI Prompt Studio](https://hanaumi-haruka.github.io/NovelAI-Prompt-Studio/)**。支持电脑和手机浏览器，无需安装开发工具。

[项目仓库](https://github.com/HanaUMI-Haruka/NovelAI-Prompt-Studio) · [v0.1.0 源码下载与发布说明](https://github.com/HanaUMI-Haruka/NovelAI-Prompt-Studio/releases/tag/v0.1.0) · [问题反馈](https://github.com/HanaUMI-Haruka/NovelAI-Prompt-Studio/issues)

在线版需要联网加载网页和词库；本地运行在首次安装依赖后可离线使用。个人数据保存在当前浏览器，不会自动跨设备同步；换设备或从本机切换到在线版，请先用“备份恢复”迁移数据。

## 项目能解决什么问题

写绘画提示词时，经常需要查找英文标签、手动拼接词条、调整顺序和权重，还要反复整理常用搭配。本项目把这些操作放到同一个界面中：

- **想得到中文描述，却记不住英文标签**：用中文、英文或已收录别名搜索词库，选择对应的英文词条。
- **反复修改 Prompt 容易漏词或打乱顺序**：通过已选标签块调权、拖动和临时停用，实时查看输出。
- **常用搭配每次都要重新选择**：把单个标签或带顺序、权重的标签组合存进收藏夹，之后直接追加。
- **自己的词条没有地方保存**：在个人标签库中手动维护中英文标签，并像普通卡片一样点选。

本项目的产物是**提示词文本**，不会生成图片，也不会把 Prompt 发送到生图平台。中文搜索使用已有词库映射，**不是自由中文句子的自动翻译**。

## 主要功能

| 功能 | 当前支持的行为 |
| --- | --- |
| 双语标签库 | 约33.4万条内置标签，14个大类与细分类；支持中文、英文和已收录别名搜索。数据来自固定快照，不是实时全集。 |
| 排序与翻页 | 引用次数、汉语拼音、英文三种排序，可反转方向、已选优先；支持快捷页码和输入目标页。拼音/英文排序时，数字与符号开头的名称在两个方向中都置后。 |
| 引用屏蔽 | 开关、预设门槛和手动输入；设置区域可折叠。只隐藏列表中的低引用或未知引用词条，不删除已有 Prompt 或收藏；个人标签不受门槛屏蔽。 |
| Prompt 编辑 | 点选去重、移除、整块拖动顺序、逐标签权重和临时启停，输出实时更新。权重范围为0–3，默认1；排序标签库不会改变 Prompt 顺序。 |
| 自定义文本与复制 | 手动补充正向文本、编辑排除提示词，分别复制正向和排除 Prompt。生成的正向输出框只读，通过选词和编辑区修改内容。 |
| 收藏夹与组合 | 新建、重命名、删除收藏夹；星标收藏单个标签；保存标签组合并追加使用，重复标签保留当前权重和启停状态。 |
| 个人标签库 | 直接新建、编辑、删除自定义中英文词条，卡片点选加入 Prompt；显示全部个人标签，不提供搜索、分类筛选或引用屏蔽。内置词条另可保存个人译名、别名和分类修正，英文原名保持。 |
| 本地数据 | 草稿自动保存、当前会话最多10步撤销/重做、JSON备份及合并/恢复；读取失败时保护原数据，保存失败时提示。 |
| 主题与手机 | 五种浅色/深色主题；手机通过“标签库”“已选标签”“输出”切换操作。电脑可直接按住标签块拖动，手机长按后拖动。 |

收藏组合只保存所选标签的顺序、权重及启停状态，**不包含手填的正向文本或排除提示词**；保存和迁移完整草稿请使用“备份恢复”。撤销历史在刷新后清空，收藏夹、个人词典定义及设置的修改不属于草稿撤销历史。

## 安装或访问方法

### 直接在线使用

打开 [在线编辑器](https://hanaumi-haruka.github.io/NovelAI-Prompt-Studio/) 即可使用，电脑和手机均可访问，不需要 GitHub 账号或 Node.js。首次打开需要下载完整词库和排序索引，请等待“词库已就绪”。

浏览器缓存不能替代完整离线支持。当前在线版没有可安装的 PWA 或离线缓存机制，断网后重新打开或刷新可能无法加载；需要可靠的离线使用时，请选择下方本地运行方式。

### 本地运行源码

从 [Release](https://github.com/HanaUMI-Haruka/NovelAI-Prompt-Studio/releases/tag/v0.1.0) 下载 `Source code` 并解压，或克隆本仓库。源码不是安装包，也不能直接双击 HTML 运行。推荐安装 **Node.js 24 LTS**（包含 npm）；`package.json` 声明的最低版本为 Node.js 22.12。在含有 `package.json` 的项目根目录打开终端：

```sh
npm ci
npm run dev
```

打开终端显示的地址，默认通常是：

```text
http://127.0.0.1:5173/
```

端口被占用时 Vite 会选择其他端口，**以终端实际输出为准**。首次安装需要联网下载依赖；标签快照已经随源码提供，无需再抓取 Danbooru、运行 Python 或配置密钥。

依赖准备完成后，本地运行不需要连接互联网，但本地服务需要保持运行。手机使用在线版最方便；手机也可以在同一局域网访问电脑提供的服务，需要另行配置监听地址和防火墙，默认 `127.0.0.1` 仅本机可访问。

Windows 如果提示 `npm.ps1` 被执行策略阻止，可使用以下命令，无需调整系统执行策略：

```powershell
npm.cmd ci
npm.cmd run dev
```

### 在线访问与静态部署

在线版本已部署到 [GitHub Pages](https://hanaumi-haruka.github.io/NovelAI-Prompt-Studio/)，可以直接在浏览器中使用。仓库自带**手动触发**的 GitHub Pages 工作流；后续更新代码后，需要重新运行 `Deploy GitHub Pages` 才会更新网站。

需要部署时运行：

```sh
npm run build
npm run preview
```

`build` 生成 `dist/`；`preview` 用于本地检查生产产物，默认地址为 `http://127.0.0.1:4173/`，也以终端输出为准。部署时上传整个 `dist/`，保留词库、排序索引和许可证目录。不要直接双击 HTML，也不要把 `preview` 当作生产服务器。

仓库子路径部署、Pages设置和其他托管方式见[部署说明](docs/DEPLOYMENT.md)；准备干净源码及上传步骤见[发布说明](docs/RELEASING.md)。

## 使用方法

1. **寻找标签**：进入“标签库”，输入中文、英文或别名，或使用大类和细分类查找。按需要设置排序、引用门槛和页码。
2. **选择标签**：点击卡片加入已选列表。已选卡片会高亮并显示“已选择”，再次点击移除。星标按钮用于收藏，不会把标签加入 Prompt。
3. **调整输出**：拖动已选标签块改变先后顺序，修改权重，或点击眼睛图标临时停用。停用保留顺序和权重，但不参与当前输出；权重0仍会输出权重语法，不能替代停用。
4. **补充文本**：在“自定义标签”中手填更多英文词句，用英文/中文逗号或换行分隔，它们会追加到已选标签之后。需要排除的内容填写在“排除提示词”中，不会混入正向输出。
5. **复制使用**：点击“复制正向 Prompt”和“复制排除 Prompt”，再粘贴到自己的生图工具。手机可切换到“输出”页查看。
6. **复用搭配**：点击星标保存单标签，或点击“收藏标签组合”把所选标签存入收藏夹；在“我的收藏”中选择组合追加到当前草稿。
7. **管理个人词条**：进入“个人标签库”，点击“新增个人标签”，手动填写中文名、单个英文标签及分类。保存并关闭编辑弹窗后即可点击卡片使用；卡片铅笔可编辑，“管理个人标签”中可删除。
8. **保存与迁移**：草稿自动写入当前浏览器。需要换浏览器、换站点或保留独立副本时，用“备份恢复”下载JSON文件，在目标位置选择文件并按提示恢复。

个人标签的英文需要手动填写，不能与已有词条重复，也不能包含逗号、换行或权重控制符。删除个人标签前会显示影响并要求确认；确认后清理草稿、收藏、组合及历史中的引用，清理后为空的组合一并删除。个人定义的删除不能通过草稿撤销恢复。

## 输入输出实例

以下例子展示当前程序实际生成的文本，不代表图像效果保证。示例1和示例2分别从空的已选列表开始；例子中未提到的权重均为默认1。

### 示例1：中文选词生成英文 Prompt

按下面的顺序搜索并选择：

| 中文标签 | 对应英文 | 权重 |
| --- | --- | --- |
| 银发 | `silver hair` | 1 |
| 蓝眼睛 | `blue eyes` | 1 |
| 微笑 | `smile` | 1 |

“自定义标签”留空，正向输出为：

```text
silver hair, blue eyes, smile
```

### 示例2：设置权重并追加自定义文本

依次选择“银发、蓝眼睛、微笑”，把银发权重改为 `1.3`、蓝眼睛改为 `0.8`；在“自定义标签”中输入：

```text
soft lighting, detailed background
```

正向输出为：

```text
1.3::silver hair ::, 0.8::blue eyes ::, smile, soft lighting, detailed background
```

如果再把“微笑”拖到第一位，并用眼睛图标停用“蓝眼睛”，正向输出变为：

```text
smile, 1.3::silver hair ::, soft lighting, detailed background
```

这说明调整的是实际输出顺序；被停用的标签不出现在 Prompt 中。默认权重1不添加数值语法，其他权重按程序当前格式逐项闭合，包含示例中的空格。

### 示例3：排除提示词独立复制

在“排除提示词”中手动输入：

```text
blurry, low quality
```

点击“复制排除 Prompt”得到同样的文本，它不会自动加入正向 Prompt。这里是手动输入示例，不是对默认排除词的描述。

## 功能边界与数据说明

- 只编辑文本，不生成图片、不连接生图API、不提供自由文本自动翻译、账号或云同步；也没有智能排序、日语罗马音排序或独立角色数据库。
- 当前数值权重输出面向 NovelAI V4及以上。其他生图工具可能使用不同语法，本项目没有自动切换适配器；并非所有收录词条都已验证适用于模型。格式冲突词条会提示并限制自动加入或复制。
- 引用次数来自固定快照，中文为社区翻译，分类由本工具整理，可能存在误译或误分。完整文本词库可能包含成人相关词语，不包含图片，也不是实时 Danbooru 全集。
- 用户JSON备份不包含内置大词库或撤销历史；目前没有完整词库的通用JSON/CSV导入导出界面。数据来源、固定提交、哈希及数据库授权见[数据来源与许可](docs/DATA_SOURCES.md)。

## 隐私与本地保存

草稿、收藏夹、组合、个人标签和设置存于当前浏览器 LocalStorage，不会由应用上传。在线版由 GitHub Pages 提供，网页和词库加载会产生网络请求，托管平台可能记录访问。首次打开需下载约 20MB 标签 JSON，另有约 7.65MiB 排序索引及网页资源，实际传输量取决于压缩与缓存。

清除站点数据、使用隐私窗口或更换浏览器可能丢失内容；换域名、协议或端口后，本地存储也不会自动迁移，请先导出备份。本机预览与在线版的数据互不自动同步。备份包含你的自定义内容，分享前请检查。公开站点已启用 HTTPS；复制失败时可手动选择输出文本复制。详见[隐私说明](docs/PRIVACY.md)。

## 开发与验证

```sh
npm test
npm run build
npm run release:check
```

测试使用 Vitest；构建执行 TypeScript 检查，生成运行依赖完整许可和排序资源，再输出网页。仓库运行 Windows/Linux CI；[Actions](https://github.com/HanaUMI-Haruka/NovelAI-Prompt-Studio/actions) 提供每次提交的实际结果。Pages 部署工作流也会运行测试与发布检查。参与贡献请阅读[贡献指南](CONTRIBUTING.md)，安全问题见[SECURITY.md](SECURITY.md)。

技术栈：React 19、TypeScript 5.9、Vite 7、Tailwind CSS 3、Vitest 4、dnd-kit及Lucide。应用使用React状态和版本化LocalStorage，Prompt由结构化标签派生。

```text
src/components/    标签库、个人词条、收藏、Prompt及主题界面
src/hooks/         状态、词库加载与本地持久化
src/lib/           权重、排序、数据校验、备份和测试
src/data/          基础词条、分类规则与作品媒介映射
public/catalog/    标签快照、排序索引、派生数据库及许可
public/licenses/   运行依赖、应用及上游完整许可
scripts/           索引和许可生成、发布检查及源码准备
.github/           CI、手动Pages发布及反馈模板
docs/              安装部署、隐私、数据来源及发布说明
```
